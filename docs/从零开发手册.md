# 墨屿（Moyu）— 从零开发手册（小白照做版）

> 目标：你按阶段打勾，就能把「积分制 AI 生图」从骨架做成可上线的系统。  
> 技术主线：**阶段 A = Next.js 全栈**；**阶段 B = 再加 Python Worker + Redis**。  
> 配套阅读：`docs/产品方案.md`、`docs/技术方案.md`、`docs/小白入门-架构与业务.md`  
> **完整可复制代码**：[`docs/从零开发手册-完整代码.md`](./从零开发手册-完整代码.md) ← **写代码时打开这个**  
> **建议阅读顺序**：主手册看阶段与验收 → 代码附录复制文件 → 概念不懂再翻《小白入门》。  
> 重要澄清：本项目用的是 **Next.js**，不是 NestJS。

---

## 怎么用这份文档

1. **不要跳阶段**：先 Phase 0 → 1 → 2…；没做完鉴权就别接支付。  
2. 每一节有：**目标 / 你要改哪些文件 / 步骤 / 验收标准 / 常见坑**。  
3. **具体代码不要只在本章找**：请打开 **[`从零开发手册-完整代码.md`](./从零开发手册-完整代码.md)**，里面是按文件路径组织的完整可粘贴实现（认证、预扣生图、历史、Mock 充值、Worker 示意）。  
4. 仓库里 **UI 大多已有**，多数 `/api/*` 还是 `501`。你的主线是把 **API + 数据库真实逻辑** 补齐，并改前端去调真接口。  
5. 厂商 API / OSS SDK 字段以官方文档为准；附录里的 Mock Provider 可先不花钱跑通闭环。  
6. 遇到报错：先看终端日志，再核对 `.env` 与验收清单。

## 0. 先建立正确心智模型（必读）

### 0.1 系统在干什么

```text
用户注册 → 送积分 → 写提示词 → 服务端预扣积分
→ 调混元/GPT 出图 → 图存 OSS → 前端展示
→ 没分了就充值 → 再出图
```

### 0.2 两个阶段

```text
阶段 A（先做）：
  浏览器 ⇄ Next.js（页面 + /api）⇄ 数据库
                      ↘ 直接调混元/GPT

阶段 B（以后）：
  Next.js 只负责接待与积分
  → Redis 队列 → Python Worker → 模型 / OSS
```

### 0.3 Next.js 目录口诀

| 看到 | 含义 | 例子 |
|------|------|------|
| `app/xxx/page.tsx` | 网页 | `/login` |
| `app/api/xxx/route.ts` | 后端接口 | `POST /api/generate` |
| `components/` | UI 积木 | 工作台 |
| `lib/` | 服务端可复用逻辑 | 算积分、Prisma |
| `"use client"` | 这段在浏览器跑 | 表单状态 |
| 无 `"use client"` 的 `route.ts` | 在服务器跑 | 可碰密钥 |

### 0.4 统一 API 响应格式（已有工具）

成功 / 失败请继续用 `frontend/lib/api-response.ts`：

```json
{ "ok": true, "data": { ... } }
{ "ok": false, "error": { "code": "UNAUTHORIZED", "message": "..." } }
```

前端判断：`if (!json.ok) 显示 json.error.message`。

### 目标

- 能打开 http://localhost:3000  
- PostgreSQL 能连上

## Phase 1 — 真用户体系 + 积分入库

> **完整代码直接复制**：见 [`从零开发手册-完整代码.md`](./从零开发手册-完整代码.md) 的「Phase 1」整节  
> （`password.ts` / `session.ts` / register / login / me / logout / AuthGate）

### 目标

- 注册写入数据库，密码哈希，赠送 10 积分  
- 登录发会话（Cookie 或 Token）  
- `/api/auth/me` 返回真实邮箱与积分  
- 前端去掉「纯 localStorage 假会话」依赖（或登录成功后改为以服务端为准）

### 涉及文件（重点）

| 文件 | 做什么 |
|------|--------|
| `prisma/schema.prisma` | 已有 User / Task / CreditTransaction，一般不用改 |
| `app/api/auth/register/route.ts` | 实现注册 |
| `app/api/auth/login/route.ts` | 实现登录 |
| `app/api/auth/me/route.ts` | 实现当前用户 |
| 新建 `lib/auth/*.ts` | 密码哈希、读/写 Session |
| `lib/auth-session.ts` + 登录/注册页 | 改为调用真 API |
| `package.json` | 增加 `bcryptjs`（或 `argon2`）、可选 `jose` |

### 1.1 安装依赖建议

```bash
cd frontend
pnpm add bcryptjs
pnpm add -D @types/bcryptjs
# 若用 JWT：
pnpm add jose
```

### 1.2 注册 API 逻辑（照这个顺序写）

文件：`app/api/auth/register/route.ts`

1. 解析 JSON：`{ email, password }`  
2. 校验：邮箱格式、密码 ≥ 6 位  
3. 查库：email 是否已存在 → 存在则 `fail("VALIDATION_ERROR", ...)`  
4. `bcrypt.hash(password, 10)`  
5. 事务创建用户：`credits: 10`  
6. （可选）写一条 `credit_transactions`：`type=recharge` 或单独 `gift`，amount=+10，description=注册赠送  
7. 创建 Session / 设置 Cookie  
8. `ok({ email, credits: 10 })`

### 1.3 登录 API

1. 查用户 by email  
2. `bcrypt.compare(password, user.password)`  
3. 失败 → `fail("UNAUTHORIZED", "邮箱或密码错误", 401)`  
4. 成功 → 写 Session Cookie  
5. `ok({ email, credits: user.credits })`

### 1.4 me API

1. 从 Cookie 解析当前 userId  
2. 无效 → 401  
3. 查库返回 `{ email, credits }`（**credits 永远读数据库**）

### 1.5 Session 推荐实现（小白友好）

**方案：HttpOnly Cookie + 签名 JWT（jose）**

```text
登录成功 → 签发 JWT { sub: userId, exp: 7天 }
→ Set-Cookie: session=<token>; HttpOnly; Path=/; SameSite=Lax
（生产再加 Secure）
```

新建例如：

- `lib/auth/password.ts` — hash / verify  
- `lib/auth/session.ts` — createSessionToken / getUserIdFromRequest  
- `lib/auth/cookies.ts` — 设置/清除 cookie 的辅助函数  

`getUserIdFromRequest(request: Request)` 供所有需登录的 API 调用。

### 1.6 改前端登录/注册页

`app/login/page.tsx` / `app/register/page.tsx`：

1. `fetch("/api/auth/login", { method:"POST", headers:{"Content-Type":"application/json"}, body: JSON.stringify({email,password}), credentials: "include" })`  
2. 成功后 `router.replace("/workspace")`  
3. 可暂时仍写一份 localStorage 缓存邮箱/积分做展示，但 **以 `/api/auth/me` 刷新为准**

`AuthGate` / `useClientSession`：

- 改为：挂载时请求 `/api/auth/me`；401 则跳转登录  
- 不要只信 localStorage

### 1.7 验收标准

- [ ] Prisma Studio 能看到新用户，password 不是明文  
- [ ] 注册赠送 credits=10  
- [ ] 错误密码无法登录  
- [ ] 登录后 `/api/auth/me` 返回正确积分  
- [ ] 退出后 me 返回 401（实现 logout：清 Cookie）

### 1.8 常见坑

- 前端 `fetch` 忘了 `credentials: "include"`，Cookie 带不上。  
- 密码明文入库（绝对不行）。  
- 只改 localStorage 的 credits，数据库没变。

## Phase 2 — 生图主链路（预扣 + 任务 + 出图）

> **完整代码直接复制**：见 [`从零开发手册-完整代码.md`](./从零开发手册-完整代码.md) 的「Phase 2」  
> （Mock Provider、完整 `generate` 预扣/退分、`status`、工作台 fetch、GPT 示意）

### 目标

打通：

```text
工作台点生成 → POST /api/generate
→ 预扣积分 + 写任务
→ 调用模型（或先 Mock）
→ 更新任务 done/failed
→ 前端展示图或错误；失败退分
```

建议拆成 **2A Mock 出图** → **2B 接真模型**。

### 涉及文件

| 文件 | 做什么 |
|------|--------|
| `app/api/generate/route.ts` | 主流程 |
| `app/api/status/[id]/route.ts` | 查任务 |
| `lib/credits.ts` | 已有算费，可复用 |
| `lib/models.ts` | 模型版本与 baseCost |
| 新建 `lib/providers/*.ts` | 模型适配 |
| `lib/env.ts` | 读取并校验环境变量 |
| `components/generate/generate-workspace.tsx` | 接真 API + 轮询 status |

### 2.1 费用规则（已有约定）

见 `calcGenerationCost(modelVersionId, mode)`：

- 版本 `baseCost`（混元标准约 2，GPT 约 3…）  
- 图生图再 +1  

生成前前端已展示预计消耗；服务端必须 **再算一遍**，不信任前端传来的 cost。

### 2.2 `POST /api/generate` 实现清单

按顺序实现，不要调换：

1. **鉴权**：`userId = await getUserIdFromRequest(request)`，否则 401  
2. **校验 body**：已有 `generateBodySchema`（Zod）  
3. **算 cost**：`calcGenerationCost(parsed.modelVersion, parsed.mode)`  
4. **图生图额外校验**：该版本是否 `supportsImageToImage`；需要 `refImageUrl`  
5. **数据库事务**（Prisma `$transaction`）：  
   - 读用户 credits  
   - 若 `credits < cost` → `fail("INSUFFICIENT_CREDITS", ..., 402或400)`  
   - `UPDATE User SET credits = credits - cost WHERE id=userId AND credits >= cost`  
   - 写 `CreditTransaction`：`type=generation`，amount=`-cost`  
   - 写 `GenerationTask`：status=`pending`（或直接 `processing`）  
6. **调模型**（阶段 A 同步简化）：  
   - 先把 task 更新为 `processing`  
   - 调用 Provider  
   - 成功：`status=done`，`resultUrl=...`  
   - 失败：同一事务或紧接事务：退分 + `type=refund` + `status=failed` + `errorMessage`  
7. **返回**：

```json
{
  "ok": true,
  "data": {
    "taskId": "...",
    "cost": 2,
    "creditsLeft": 8,
    "status": "done",
    "resultUrl": "https://..."
  }
}
```

同步模式可直接 `status=done`；若改异步，先返回 `pending`，前端轮询。

### 2.3 Phase 2A：Mock Provider（强烈建议先做）

新建 `lib/providers/mock.ts`：

- `generate()` 等 1–2 秒  
- 返回一张固定图 URL（例如公开 placeholder 图）或 data URL  

好处：不花钱就能验证 **扣分 / 退分 / 前端展示**。

### 2.4 Phase 2B：真模型 Provider

统一接口建议：

```ts
type GenerateInput = {
  modelVersion: string;
  mode: "text_to_image" | "image_to_image";
  prompt: string;
  size: string;
  refImageUrl?: string | null;
};

type GenerateOutput = { imageUrl: string }; // 或 buffer，再上传 OSS
```

实现：

- `lib/providers/hunyuan.ts`  
- `lib/providers/gpt.ts`  
- `lib/providers/index.ts` — `getProvider(modelFamily)`  

密钥只从 `process.env` 读，例如：

```env
HUNYUAN_API_KEY=...
OPENAI_API_KEY=...
```

**禁止** `NEXT_PUBLIC_` 前缀暴露密钥。

具体 HTTP 路径、字段名：打开厂商文档对照实现；本手册不绑定易过期的 URL。

### 2.5 `GET /api/status/[id]`

1. 鉴权  
2. 查 task，且 `task.userId === 当前用户`（防越权）  
3. 返回 `{ id, status, resultUrl, errorMessage, cost, createdAt }`

### 2.6 改工作台前端

`generate-workspace.tsx` 当前已 `fetch /api/generate`：

1. 带上 `credentials: "include"`  
2. 成功后：  
   - 若直接 `done`：`setResultUrl(data.resultUrl)`，并刷新积分（调 me）  
   - 若 `pending`：每 1–2 秒 `GET /api/status/[id]`，直到 done/failed  
3. `INSUFFICIENT_CREDITS`：提示去充值  
4. failed：展示 `error.message`，积分应已退回（再拉一次 me）

### 2.7 验收标准

- [ ] 积分从 10 → 扣费后变少，流水表有记录  
- [ ] Mock/真模型能出图并显示在右侧  
- [ ] 故意让 Provider 抛错：积分退回，task=failed  
- [ ] 余额不足无法生成  
- [ ] 不能查询别人的 taskId  

### 2.8 常见坑

- 只扣分不写 task / 只写 task 不扣分。  
- 失败不退分。  
- 前端算 cost、后端不校验。  
- 同步调用不设 timeout，请求挂死。

## Phase 3 — 历史、OSS、第二模型、图生图

### 目标

- 历史列表可看可下载  
- 参考图与结果图进对象存储  
- GPT + 图生图可用  

### 3.1 历史 API：`GET /api/history`

1. 鉴权  
2. 分页：`?page=1&pageSize=20`  
3. `findMany` where userId，orderBy createdAt desc  
4. 返回任务摘要：prompt、model、mode、status、resultUrl、cost、时间  

### 3.2 改 `app/history/page.tsx`

把占位 UI 换成真实列表：缩略图、状态、再次填入工作台（可选）。

### 3.3 对象存储 OSS/COS

#### 为什么要做

模型常返回临时链接；你应把图落到自己的桶，路径可长期访问（或签名 URL）。

#### 步骤

1. 云厂商开通桶，拿到 AccessKey（只放服务端 `.env`）  
2. 安装官方 SDK（阿里云 OSS / 腾讯云 COS 选其一）  
3. 新建 `lib/storage.ts`：`uploadBuffer(key, buffer, contentType) → url`  
4. 生成结果后：下载模型图 → upload → 把 **自有 URL** 写入 `resultUrl`  
5. 图生图参考图：  
   - 前端可先 `POST /api/upload`（你新建）拿 URL，再带 `refImageUrl` 去 generate  
   - 或 generate 改用 `multipart/form-data`（稍难，可后做）

路径建议：

```text
uploads/{userId}/{uuid}.png
results/{userId}/{taskId}.png
```

限制：仅 jpg/png/webp；大小例如 ≤ 5MB。

### 3.4 第二模型 + 图生图

1. `getProvider("gpt")` 调通文生图  
2. 工作台切换模型系列已存在，确保 API 按 `model` / `modelVersion` 分支  
3. 图生图：校验 `refImageUrl` + 版本支持；cost = base + 1  
4. Provider 按厂商文档传参考图参数  

### 3.5 验收

- [ ] 历史页能看到自己的成功/失败任务  
- [ ] 结果 URL 来自你的 OSS（不是过期的临时链）  
- [ ] 混元与 GPT 都能文生图  
- [ ] 图生图至少一条链路跑通

## Phase 4 — 充值与支付

### 目标

用户买积分包 → 支付 → 回调入账 → 余额增加。

### 4.1 数据

建议新增表 `recharge_orders`（在 schema 里加 model 再 migrate）：

| 字段 | 说明 |
|------|------|
| id | 订单 ID |
| userId | 用户 |
| packageId | basic/standard/pro |
| amountFen | 金额（分） |
| credits | 应加积分 |
| status | pending / paid / closed |
| channel | wechat / alipay |
| providerTradeNo | 第三方单号 |
| createdAt / paidAt | 时间 |

### 4.2 已有套餐接口

`GET /api/recharge/packages` 已有雏形，对齐产品方案：

| 套餐 | 价格 | 积分 |
|------|------|------|
| 基础 | 9.9 | 50 |
| 标准 | 29.9 | 200 |
| 专业 | 99 | 800 |

### 4.3 `POST /api/recharge/create`

1. 鉴权  
2. 校验 packageId  
3. 创建订单 status=pending  
4. 调微信/支付宝「预下单」API，返回支付参数给前端  
5. **沙箱/模拟模式**：开发阶段可做 `POST /api/recharge/mock-pay` 仅本地把订单置 paid 并加积分（生产关掉）

### 4.4 `POST /api/recharge/webhook`

1. 验签（厂商文档）  
2. 找订单  
3. 若已是 paid → 直接返回成功（**幂等**）  
4. 事务：订单→paid；user.credits += n；写 credit_transactions type=recharge  
5. 返回渠道要求的成功应答  

### 4.5 前端

- 新建 `/recharge` 页或工作台余额旁入口  
- 展示套餐 → 创建订单 → 拉起支付 → 支付后轮询 me / 订单状态  

### 4.6 验收

- [ ] 支付成功积分增加且有流水  
- [ ] 同一回调打两次，积分只加一次  
- [ ] 未支付订单不会加积分  

### 4.7 常见坑

- 信任前端「我付过了」直接加积分（禁止）。  
- 回调不做幂等导致重复加分。

## Phase 5 — 阶段 B：Python Worker + Redis（可选）

> 仅当：同步生图经常超时、要批量/重处理、或要上复杂图像管线时再做。  
> 在此之前，**把 Phase 1–4 做稳更重要**。

### 目标

```text
Next.js：鉴权 + 预扣 + 写 task(pending) + 入队 + 立刻返回 taskId
Redis：队列
Python Worker：消费 → 调模型 → 上传 OSS → 更新 DB（done/failed + 退分）
前端：轮询 status
```

### 5.1 启动 Redis

```bash
docker compose --profile worker up -d redis
```

### 5.2 改造 Next.js generate

事务内预扣 + 创建 task 后：

- **不要**在请求里长时间 await 模型  
- `queue.add({ taskId, ... })`  
- 返回 `{ status: "pending", taskId, cost, creditsLeft }`

可用 BullMQ（Node）或把任务 ID 推进 Redis List，由 Python 去 `BRPOP`。

### 5.3 Python 侧（仓库已有骨架）

```bash
cd worker
python -m venv .venv

```

## 附录 C — 伪代码：生成事务（务必理解）

```text
BEGIN
  锁定或条件更新用户积分
  IF 余额不足 THEN ROLLBACK; 返回错误
  credits -= cost
  INSERT credit_transactions (generation, -cost)
  INSERT generation_tasks (pending/processing, cost)
COMMIT

尝试调模型
IF 成功:
  UPDATE task SET done, result_url
ELSE:
  BEGIN
    credits += cost
    INSERT credit_transactions (refund, +cost)
    UPDATE task SET failed, error_message
  COMMIT
```

## 总结

你按 **Phase 0 → 6** 推进即可：先环境，再人与积分，再出图，再历史与存储，再收钱，最后才拆 Worker。  

核心工程原则始终是：

> **积分事务正确、密钥不出前端、架构可拆不可先拆、验收打勾再进入下一阶段。**

若某一步卡住，把「当前 Phase + 报错原文 + 相关文件路径」记下来，再针对性查官方文档或请人帮看；不要跳过验收去堆新功能。
