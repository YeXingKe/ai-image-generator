# 墨屿 — 产品方案

> 品牌：墨屿（Moyu）  
> 版本：MVP v1.0  
> 定位：低门槛、按积分付费的 AI 图像生成 SaaS  
> 技术前提：先用 Next.js 全栈跑通，后续按需拆出 Python AI 服务

---

## 1. 背景与机会

AI 生图已从早期的「随机开盲盒」阶段，逐步走向高确定性的工业流协作。行业正从「模型秀肌肉」走向「工作流竞争」——用户不再只关心「能不能出图」，而是关心：

- 是否稳定、可控、可复用
- 成本是否可预期
- 是否能嵌入日常创作/电商/内容生产流程

当前主流大厂（混元、GPT Image、通义等）已提供成熟的云端 API，独立开发者无需自建 GPU，即可通过「调用云端模型 + 自建付费壳」快速落地付费产品。

**本产品的切入点：** 用最简技术栈，快速上线「文生图 / 图生图 + 多模型切换 + 积分付费」的最小可行产品（MVP），验证付费意愿后再扩展能力。

---

## 2. 市场定位与目标用户

### 2.1 产品定位

**墨屿**面向个人创作者与小微商家的 **轻量 AI 生图工具**：注册即用、按次计费、支持主流模型切换，不做复杂工作流编辑器，先把「出图 → 付费 → 再出图」闭环做顺。

### 2.2 目标用户分层

| 用户层 | 典型角色 | 核心诉求 | MVP 覆盖 |
|--------|----------|----------|----------|
| C 端普通用户 | 个人、学生、娱乐用户 | 低门槛、趣味性；头像、朋友圈配图 | ✅ 重点 |
| B 端小微商家 | 电商卖家、自媒体运营 | 商品图、营销海报、批量感不强但要快 | ✅ 重点 |
| 创意工作者 | 设计师、内容创作者 | 灵感探索、草图生成、风格试错 | ✅ 部分覆盖 |

### 2.3 非目标（MVP 阶段明确不做）

- 企业级协作与团队空间
- 复杂节点式工作流编排
- 自部署开源模型（Stable Diffusion 等）
- 设计师级修图工具（局部重绘、图层、PSD 导出等）

## 3. MVP 核心功能

第一版只聚焦五件事，保证闭环可跑通、可收费。

| 功能模块 | 说明 | 优先级 |
|----------|------|--------|
| 文生图 | 用户输入文字描述，系统生成图片 | P0 |
| 图生图 | 上传参考图 + 文字描述，生成新图 | P0 |
| 模型切换 | 支持「混元生图」与「GPT 生图」切换 | P0 |
| 积分充值 | 用户充值购买积分，每次生成消耗积分 | P0 |
| 历史作品 | 查看、下载、管理已生成图片 | P0 |

### 3.1 暂不包含（后续迭代）

- 批量生成
- 局部重绘 / Inpainting
- 高清放大 / 超分
- 模板市场 / Prompt 市场
- 风格预设库深度运营
- 团队协作与共享空间
- 自部署开源模型

## 4. 用户流程

```
注册 / 登录
    ↓
获赠免费积分（体验包）
    ↓
选择模型（混元 / GPT）
    ↓
选择模式（文生图 / 图生图）
    ↓
输入提示词（图生图时上传参考图）
    ↓
点击生成 → 积分预扣 → 异步生成
    ↓
展示结果 → 下载 / 重试 / 再次生成
    ↓
积分不足时引导充值
```

### 4.1 关键体验原则

1. **先体验后付费**：注册赠送少量积分，降低首次尝试成本。
2. **生成过程可感知**：异步任务 + 状态轮询，避免「卡住无反馈」。
3. **失败可挽回**：生成失败自动退还积分，并给出可读错误提示。
4. **充值路径短**：积分不足时一键进入充值，减少流失。

## 5. 商业模式与定价

### 5.1 收费模式

采用 **按积分付费**：

- 注册赠送体验积分
- 用户购买积分包
- 每次生图按模型与模式扣减积分

### 5.2 积分套餐（建议价）

| 套餐 | 价格 | 积分 | 折合单价 |
|------|------|------|----------|
| 体验包 | 免费注册赠 | 10 积分 | — |
| 基础包 | ¥9.9 | 50 积分 | ¥0.198 / 次 |
| 标准包 | ¥29.9 | 200 积分 | ¥0.149 / 次 |
| 专业包 | ¥99 | 800 积分 | ¥0.124 / 次 |

> 定价目标：覆盖 API 成本 + 存储流量 + 合理毛利；大额包单价更低，促进客单提升。

### 5.3 积分消耗规则

| 操作 | 消耗 |
|------|------|
| 混元生图（文生图） | 2 积分 / 次 |
| GPT 生图（文生图） | 3 积分 / 次 |
| 图生图（任一模型） | 在对应模型基础上 +1 积分 |

### 5.4 成本与毛利原则（产品侧约束）

- 单次售价（积分折算）应高于对应模型 API 成本 + 对象存储/流量成本。
- 体验包积分总量可控，防止刷量；可对免费积分限制日用量或设备风控。
- 后续可按模型成本动态调整扣费规则，前端展示「本次预计消耗」。

```

```

## 7. 关键体验（UX）要点

1. **工作台优先**：首屏即生图操作区，减少跳转。
2. **成本透明**：提交前展示本次预计扣分；余额不足时禁用按钮并引导充值。
3. **结果可操作**：下载原图、复制 Prompt、一键改 Prompt 再生成。
4. **历史可追溯**：保留 Prompt、模型、模式、消耗积分、时间。
5. **移动端可用**：核心流程在手机浏览器可完成（上传、生成、下载）。

---

## 8. 风险、合规与风控（产品侧）

| 风险 | 产品应对 |
|------|----------|
| 违规内容生成 | 接入模型侧安全策略；前端提示词规范说明；保留任务日志便于追溯 |
| 刷免费积分 | 注册验证、设备/IP 限流、免费积分日上限 |
| 支付纠纷 | 充值订单可查；积分流水可对账；失败自动退积分 |
| API 成本失控 | 预扣积分 + 并发限制 + 单用户速率限制 |
| 用户预期过高 | 文案明确「AI 生成结果有随机性」，支持重试 |

## 9. 成功指标（MVP）

| 指标 | 说明 | 建议关注 |
|------|------|----------|
| 注册转化 | 访问 → 注册 | 漏斗第一关 |
| 首次出图率 | 注册 → 完成至少 1 次生成 | 验证产品是否「开箱即用」 |
| 付费转化率 | 用完免费积分 → 充值 | 核心商业验证 |
| 次日留存 | 注册后次日回访 | 是否有持续需求 |
| 单次生成失败率 | failed / 总任务 | 技术与体验健康度 |
| API 毛利率 | （积分收入 - API/存储成本）/ 收入 | 能否可持续 |

## 10. 产品路线图

| 阶段 | 周期建议 | 内容 | 目标 |
|------|----------|------|------|
| Phase 1 | 1–2 周 | 注册登录 + 积分 + 文生图（仅混元） | 跑通闭环 |

| Phase 4 | 持续 | UI 优化、性能、风控、用户反馈迭代 | 留存与毛利 |

### 后续可选增强（验证付费后再做）

- Prompt 模板 / 风格库
- 批量生成与队列优先级（付费用户优先）
- 高清放大、局部重绘

- 自建模型 Worker（有 GPU 需求时再引入 Python 微服务）

## 11. 与技术方案的衔接说明

产品方案决定「做什么、为谁做、怎么收费」；技术方案决定「怎么实现、如何扩展」。

本产品 MVP 推荐采用：

- **现阶段**：Next.js 全栈直接调用混元 / GPT 云端 API（降本、快速上线）
- **成长期**：将 AI 调用抽成独立 Python Worker + 任务队列（便于自部署模型与复杂图像处理）

详细系统架构、数据库、接口与部署见同目录《技术方案.md》（`docs/技术方案.md`）。

---

## 12. 总结

本产品是一个 **积分制 AI 生图 SaaS MVP**：用最少功能验证「用户愿不愿为出图付费」。核心闭环是 **登录 → 出图 → 扣积分 → 充值 → 再出图**。功能做减法，商业做闭环，技术留扩展口——先活下来，再长出来。
